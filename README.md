# Can a language model repair a network's weights by reading them?

Code, frozen rules and complete run records for the extended abstract of the same title (`paper/`). Everything needed to recompute every number in the paper is here; nothing was re-run for release.

## Layout

- `paper/` — the extended abstract (LaTeX, ICLR 2027 workshop style) and its bibliography.
- `code/` — the Python package `wsp` (network, oracle, SAT identifiability, sandbox, editors, projected gradient, studies, analysis) with its tests, `pyproject.toml` and `uv.lock`. `uv sync --extra dev && uv run pytest -q wsp` runs the offline test suite; no test makes a model call.
- `rules/` — the decision rules, each frozen before the first model call of the experiment it governs, with dated amendments appended below the original text. The outcome vocabulary and precedence in the paper come from these files verbatim.
  - `calibration-rule.md` — task-size calibration before the constructor pilot.
  - `query-study-rule.md` — the query-policy study (adversarial versus random queries).
  - `redesign-rule.md` — the constrained numeric-editing study (Experiment 2 in the paper).
  - `second-model-rule.md` — the replication of both experiments with a second editor model.
  - `search-calibration-rule.md` — the follow-up black-box search calibration on development seeds.
- `records/` — one directory per experiment: the frozen configuration, every model attempt with its parse and budget status, every charged oracle query, per-round weights and endpoints, the analysis output (`study.json`, `study.md`, `RESULTS.md`), spend ledgers and launch logs.
  - `pilot/` — Experiment 1 (constructor pilot), with the accepted constructors under `run/` and the starting-point calibration under `calibration-d0/`.
  - `calibration/` — the two constructor sources from the task-size calibration.
  - `query-study/` — the query-policy study (main roster, extension, two sensitivity rosters).
  - `redesign/` — Experiment 2: the primary strict-format run (`run/`), the seed-1 correction (`run-seed1/`), the relaxed-format rerun specified after execution (`run-relaxed/`), the seed-selection preflight and its recheck, and `derived/` (both-set outcome, replay of first attempts, offline scoring of rejected proposals), regenerated by the released analyzer.
  - `second-model/` — the second-editor replications: `pilot-astra/` (Experiment 1) and `repair-astra/` (Experiment 2).
  - `search-calibration/` — the black-box search calibration, with every cell under `cells/`.

## Reproducing the analyses (offline, no model calls)

From `code/`:

```
uv run python -m wsp.repair_study report --out ../records/redesign/run          # as-run seed set 15,20,21,24,30
uv run python -m wsp.repair_study report --out ../records/redesign/run-relaxed  # relaxed-format rerun, seeds 1,15,20,21,24
uv run python -m wsp.repair_study report --out ../records/second-model/repair-astra
uv run python -m wsp.redesign_extras --main ../records/redesign/run --seed1 ../records/redesign/run-seed1 --relaxed ../records/redesign/run-relaxed --out ../records/redesign/derived
uv run python -m wsp.query_analysis --out ../records/query-study
uv run python -m wsp.search_calibration report --out ../records/search-calibration
```

The `report` commands rewrite `study.json` and `study.md` in place inside the record directory they are given (`--out` names the record directory, not a separate destination). The `redesign_extras` command writes the three derived records the paper's Experiment 2 relies on into `records/redesign/derived/`: the outcome over both seed sets (production-order set 1, 15, 20, 21, 24 combines `run-seed1/` with `run/`), the relaxed-parser replay of every rejected first attempt, and the offline scoring of the 39 rejected proposals. Each command rewrites `study.json` and `study.md` in place from the seed records; the outputs should match the committed files.

## Re-running an experiment

The `run` subcommands call a model through OpenRouter and spend money. They read the API key from the environment variable `OPENROUTER_API_KEY` only; nothing in this repository contains a key. (The runs were made with a client that could also read a local key file; key resolution has no effect on any result.) The exact commands, seeds and caps are in each experiment's `launch.log` and `study_meta.json`.

## Model outputs

The records contain verbatim outputs of the editor models under test (constructor source files, numeric edit proposals and the prose around them), released as experimental data.
