# Calibration notes — 2026-11-04 (Opus 5.5 via OpenRouter, 16k reasoning)

First sweep, one D0 editor call per k, all three failed in the harness, none
produced a scored D0:
- k=6: constructor rejected by the audit (`import sys`, used for
  `sys.setrecursionlimit`). Source: opus-d0-k6-attempt1.py.
- k=8: the model's response was a refusal (content_filter, content null) —
  Opus refuses this prompt occasionally too; Fable refused it every time.
- k=10: constructor exceeded the 10 s sandbox wall clock. Source:
  opus-d0-k10-attempt1.py.

What the model does (both sources): embeds the whole labeled dataset as a
string literal, builds the prefix-tree acceptor, runs a backtracking exact
DFA identification over state bounds n = 1.., and compiles the found DFA into
RNN weights with a one-hot state encoding and saturating tanh (gain K=10).
That is a symbolic learner plus a compiler, written by the LLM, not weights
reasoned out by hand. It is inside the spec's stated claim ("gradient-free
LLM-directed weight synthesis, not pure reasoning") and the audit's
literal-match report is the designed detector for it. Consequences for the
pilot: the editor's "repair" will be re-identification on initial +
counterexamples, so arm A vs B reduces to which labels identify the DFA
faster — the information arm of the split. The identifiability bit and the
SAT baseline are exactly the right comparators. The run stays worth doing;
the reading of the result must say this.

Harness consequences: attempt loop with failure feedback; a
constructor wall clock of 60 s (SAT baseline gets 30 s per solve); report
per-round source size and literal-match count in results.md.

## Local replay of the two constructors (no model calls), 60 s budget
- k=6 source with the two `sys` lines removed: runs in 0.2 s, D0 accuracy
  train 1.000 / held-out 1.000 / long 1.000. The backtracking identifier
  recovers the 6-state DFA from the 96 initial labels (consistent with the
  SAT baseline: unique at 96 labels). So at k=6, D0 already solves the task
  and the rule's window [0.60, 0.90] correctly excludes it.
- k=10 source: runs in 27.5 s, D0 accuracy 0.23 / 0.21 / 0.24 — below
  chance. The compile uses two hidden units per DFA state (state × symbol),
  so h=16 holds at most 8 states; beyond that the indices overflow the
  tensors and the weights are garbage. This is the representation ceiling
  the three-way split is designed to expose: k=8 sits exactly at capacity.
- Detector gap: `audit.literal_matches` reported 0 for both sources although
  the entire dataset is embedded, because the data is one multi-line string
  literal and the audit compares whole literals to observed strings. Fixed
  in the audit: match observed strings as whole tokens inside any literal.

Finding so far, stated plainly: with Opus 5.5 as editor, D0 is perfect at
every k where the 96 initial labels identify the DFA (6, 7, 8) and at chance
where they do not (10). The model's constructor is an exact DFA identifier
plus a compiler; "weight synthesis" is program synthesis. k cannot reach the
window [0.60, 0.90]; the information content of the initial set can. The
knob is n_initial, chosen offline by the SAT identifiability bit.
